# ADR-001: FitFlow Technology and Architecture

## Status

Proposed

## Context

FitFlow requires structured storage for user, workout and nutrition information, an AI service for personalised recommendations, and real-time functionality for social and notification features.

The system must also support maintainability, scalability and appropriate protection of health and fitness data.

## Decision

The proposed architecture uses:

* React Native for the frontend
* Node.js with NestJS for the backend
* PostgreSQL for structured application data
* Firebase Authentication for authentication
* Firebase Firestore for real-time social functionality
* Firebase Cloud Messaging for notifications
* Python/FastAPI for the AI microservice
* Redis for caching

## Reasons

This combination achieved the highest score in the Activity 3 weighted decision matrix with a score of 4.15 out of 5.0.

It provides:

* Strong cross-platform development
* Good maintainability
* Relational data consistency
* Real-time functionality
* Independent AI service scaling
* A mature technology ecosystem

## Alternatives Considered

### Option B

React Native + Node.js/Express + Firebase only

Weighted score: 3.75 / 5.0.

### Option C

Flutter + FastAPI + PostgreSQL + Firebase

Weighted score: 3.95 / 5.0.

## Consequences

The proposed architecture introduces more components than a Firebase-only solution.

This increases operational complexity but provides stronger separation between structured application data, real-time functionality and AI processing.

The AI service can also be changed or scaled independently of the main backend.
